1. Briefing Comercial

Categoria: Sistema metodológico de execução.

Problema: Muitas ferramentas de produtividade transferem ao usuário o trabalho de configurar, organizar, priorizar e reconstruir continuamente o próprio sistema.

Tese: Organização não deve se transformar em trabalho antes do trabalho.

Promessa: Menos tempo administrando o trabalho. Mais capacidade para executá-lo.

Proposta de valor: O Executar organiza, decompõe, prioriza e preserva contexto para transformar objetivos em próximas ações claras.

Big Idea: O aplicativo desenhado para você sair dele.

Princípio de marca: Organizar é função do sistema. Executar é função sua.

CTA mestre: Pare de organizar. Comece a executar.

Razões para acreditar: metodologia explícita; gestão de projetos/processos; IA especializada; design cognitivo; estrutura orientada a entregáveis; transparência sobre evidências e hipóteses.

  

2. Competitive Narrative

Modelo dominante

Objetivo → configurar ferramenta → organizar → priorizar → recapitular → executar

Modelo Executar

Objetivo → sistema estrutura → próxima ação → executar

O adversário narrativo não é um aplicativo específico. É o trabalho operacional criado pelo próprio sistema de produtividade.

Territórios de diferenciação:

- execução acima da organização estética;
- metodologia acima de coleção de features;
- defaults inteligentes acima de hiperconfiguração;
- IA orientada por critérios acima de geração genérica;
- contexto persistente acima de reconstrução mental;
- próxima ação acima de listas extensas.

Posição: produtividade organiza. Executar conduz à execução.

  

3. Messaging House

MASTER PROMISE  
Menos trabalho antes do trabalho.

PILAR 1 — CLAREZA  
Saiba o que fazer agora.  
Do entregável à próxima ação.

PILAR 2 — CONTEXTO  
Retome sem reconstruir tudo mentalmente.

PILAR 3 — MÉTODO

PILAR 4 — MENOS FRICÇÃO  
Você não precisa construir um sistema para começar a trabalhar.

PROVA  
Cada funcionalidade deve possuir razão, princípio aplicado e nível de evidência identificável.

  

4. Contrato de UX Copy

Toda interface deve responder prioritariamente: “O que faço agora?”

Regras

1. Começar ações com verbos concretos.
2. Uma ação principal por contexto.
3. Preferir instrução a descrição.
4. Preservar contexto de retomada.
5. Explicar prioridade quando solicitado.
6. Evitar jargão de produtividade.
7. Não usar linguagem clínica ou promessas cognitivas absolutas.
8. Reduzir escolhas sem retirar controle do usuário.

Padrões

Ação: Agora: [verbo + objeto].  
Retomada: Você parou aqui. Continue deste ponto.  
Prioridade: Esta é a próxima ação recomendada.  
Explicabilidade: Por que esta ação vem agora?  
Conclusão: [Entregável] concluído. Próximo: [ação].  
Empty state: Nada para organizar agora. Vá executar.

Teste final: se a copy aumenta dúvida, decisão ou trabalho antes da ação, deve ser reescrita.

- Sustenta o conceito do Scroll Task, mas ainda não prova especificamente o design do Executor App.

- Verbo de ação / próxima ação concreta — evidência boa, mas não pelo “verbo” isoladamente.

- Implementation intentions que especificam quando, onde e qual ação executar apresentam efeito relevante sobre início e alcance de objetivos (meta-análise, d≈0,65). 

- Entregáveis + decomposição — suporte metodológico muito forte.

- PMI define WBS como decomposição hierárquica orientada a entregáveis. 
- Importante: entregáveis são normalmente expressos como substantivos; atividades, como ações. Isso encaixa muito bem na separação Executor entre entregável → workflow → tarefa → ação.

- Hierarquizar ações/tarefas/workflows/projetos — sustentação metodológica + cognitiva.

- PMI sustenta decomposição hierárquica; Cognitive Load Theory sustenta diminuir quantidade de elementos processados simultaneamente. 

- “1, 2, 3 — primeiros três passos” — hipótese de design, não evidência direta.

- Existe evidência para decomposição, segmentação e próximos passos concretos; não encontrei sustentação para exatamente três passos.

- Auto-scroll a cada 20/30 minutos — não deve ser anunciado como cientificamente comprovado.

- Há evidência de alterações de percepção temporal em ADHD. 
- Porém, uma mudança automática pode funcionar como interrupção e gerar custo cognitivo. 
- Eu classificaria isso como funcionalidade experimental baseada em hipótese científica, preferencialmente opcional.

Formulação pública recomendada

Em vez de “todas as decisões são cientificamente comprovadas”, a formulação tecnicamente defensável seria:

“As decisões do Executor são orientadas por evidências científicas, princípios de ergonomia e interação humano-sistema e práticas consolidadas de gestão de projetos e processos. Quando não existe evidência direta para uma implementação específica, tratamos sua eficácia como hipótese de produto e a submetemos à validação.”

A base correta para adaptação do sistema ao usuário é principalmente ISO [9241-210/110](tel:9241-210/110), enquanto o PMBOK sustenta tailoring, gestão, decomposição e entregáveis. 

Essa distinção, inclusive, torna a comunicação científica do Executor mais forte e auditável, não mais fraca.
